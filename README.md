# 简历初筛助手

> 给一批校招简历（有 JD 更好），告诉 HR **先看谁、为什么**。

面向中小企业校招季的 HR 助手：读取简历（PDF / Word / TXT / 图片），调用 DeepSeek 提取事实，再由代码规则和知识库分模块给出描述性分析，最后给出分层总览或阅读队列。不打总分，每个结论都附理由。

## 解决什么问题

- **简历看不过来**：大公司有招聘系统，中小企业校招季邮箱里堆着几百份 PDF，HR 只能从头翻。
- **关键词过滤会错杀**：招聘系统按关键词筛，简历没写那个词就被刷掉。本工具以证据为核心，没写的只排在后面，不淘汰；不确定的交给人判断。

## 功能

**7 个分析模块**（每份简历都会生成一份文字报告）

| 模块 | 看什么 |
|---|---|
| 基本信息 | 只做提醒，不参与评价 |
| 教育背景 | 院校层次、学业表现（排名 / 绩点）、学业走势（专升本、跨专业、空档期等，只描述） |
| 证书荣誉 | 奖学金、竞赛（以全国大学生竞赛目录为准）、证书、科研成果 |
| 实习经历 | 平台（按公开名单定档）、经历量、工作深度：协助完成 / 独立负责 / 主导改进，有成果 |
| 校园经历 | 角色、组织级别、任期，时间是否对得上 |
| 项目与技能 | 项目可信度（有无链接、立项、获奖等）、技能深度（用它做出了什么） |
| 素质画像 | 责任心、主动性等 6 项的证据强度，并给出行为面试问题 |

**总览分层（不需要 JD）**：HR 勾选 2～3 个关心的维度（学校层次、实习经历、项目经历、技能等 9 项），只有在所选各项上都不比别人差、且至少一项更好的人才排在前面，各有所长的放同一层，每人附"为什么"。最低学历、院校、专业、证书等硬性要求只筛选、不排序。

**阅读队列（导入 JD）**：工具先解析 JD、推荐"最看重"的 3 项，HR 确认或修改后，把简历分进五个队列——优先看 / 值得看 / 可以后看 / 硬条件不符（只放确定的事实）/ 需人工查看（文件解析异常）。每人附理由和最多 3 个电话初筛问题，可导出 CSV（Excel 可直接打开）。

## 设计上的关键取舍

- **AI 只提取事实，判断由代码和知识库完成**：AI 每次结果可能不同，代码规则结果稳定、可解释；AI 填的关键字段（学历、奖学金级别、职务等）还要用代码核对原文，找不到对应字样就视为没写。
- **以证据为核心，不打总分**：别人的决定（被选举、录用、获奖）> 可核验的具体行为 > 自述；加权总分会让各项互相抵消、看不出原因，所以只输出证据强度和理由。
- **没写 ≠ 不会**：没体现的能力只排在后面，不淘汰；推断出来的事实碰到门槛只进"待确认"，交给 HR 核实。
- **只在所选各项全面不差时才分先后**：按"先比第一项、相同再比下一项"排序，等于给第一项无限大的权重，10 个人排出 9～10 个名次，是虚假的精确。
- **档位细度和判断可靠程度匹配**：学校层次来自外部排名，用细档；实习、项目深度只能从措辞判断，只用粗档。
- **合规**：性别、年龄、民族、籍贯、婚育、政治面貌不作为筛选条件，界面不提供这些选项；报告末尾声明"仅辅助阅读，不作为录用依据"（《个人信息保护法》第 24 条对自动化决策的要求）。
- **JD 知识库只爬允许的公开来源**：数据来自国家大学生就业服务平台（24365），共 28 个校招常见岗位、1596 份 JD，用于统计各岗位常见要求；robots 禁止、需要登录或有反爬验证的网站一律不爬。

## 快速开始

需要 Python 3.10 及以上和一个 DeepSeek API Key。

```bash
pip install -r requirements.txt
```

**配置 API Key**（任选一种）：

- 打开网页后在侧边栏填写（默认只在本次页面使用，勾选后才保存到本机）；
- 运行 `python setup_key.py`，在弹出的窗口里填写；
- 把 `.env.example` 复制为 `.env` 并填写 `DEEPSEEK_API_KEY`。

**打开网页版**：

```bash
streamlit run app.py        # 浏览器访问 http://localhost:8501
```

页面按 ① 岗位要求（可选）→ ② 上传简历 → ③ 总览排序 / 阅读队列 的顺序操作，内置虚构样例简历和测试 JD 可直接试用。
没有 API Key 也可以点页面上方的 **🎬 看演示**：载入 11 份虚构简历的分析结果和一份岗位要求，不调用 AI、不花钱。

**命令行版**：

```bash
# 分析虚构样例简历，输出每份的分析报告
python main.py samples/

# 不需要 JD 的总览分层
python screen.py 总览 samples samples/test/dev --排序 实习经历,项目经历,技能

# 导入 JD → 按岗位要求分队列（生成 jobs/ 下的岗位要求文件和筛选结果 CSV）
python screen.py 导入 samples/jd/数据分析工程师.txt
python screen.py 筛选 jobs/数据分析工程师.txt samples samples/test/dev
```

**测试**：`pip install -r requirements-dev.txt` 后运行 `python tests/test_job_form.py`（网页岗位要求表单的回归测试，需要 Microsoft Edge），说明见 [开发说明 · 测试](docs/开发说明.md)。

## 公开部署

可以部署到 Streamlit Community Cloud（从 GitHub 仓库直接部署）。部署时在 Secrets 里设置 `PUBLIC_DEMO = "1"` 打开**公开模式**：

- 只用访客自己在侧边栏填的 API Key，不能保存；**不要**在服务器上配置 `DEEPSEEK_API_KEY`（否则所有访客都在用你的额度）
- 不写硬盘缓存、不保存岗位要求文件：访客之间互相看不到，关掉页面就消失
- 一次最多分析 20 份简历
- `packages.txt` 让平台安装图片识别需要的系统库

演示数据在 `demo/`，分析规则改了以后运行 `python tools/build_demo.py` 重新生成（只用虚构简历）。

## 隐私

- 网页上传的简历文件分析完立即删除，分析结果只保存在浏览器会话里；公开模式下服务器不保存任何简历内容。
- AI 从简历提取的内容缓存在本机 `.cache/resumes/`，**30 天后自动删除**，网页侧边栏可一键清除。
- 手机号、邮箱、身份证号在发送给 AI 之前先脱敏。
- 仓库里只有虚构简历（`samples/`），不存放任何真实简历。

## 已知局限

- **逐字比对**：职责和能力按字面比较，同一件事换一种说法就对不上（JD 写"数据模型"、简历写"建模"），字面巧合又会误中（"清洗实验器皿"对上"数据清洗"）。虚构测试集已证实。改进方案"工作活动表"（把 JD 职责整理成约 100 项标准活动，AI 把两边都归到表里，再由代码比较）已设计，暂缓实施。
- **速度**：每份简历 5 次 AI 调用并行，长简历约 13～20 秒，目标是单份 ≤10 秒、100 份 ≤3 分钟。
- **自动测试还很少**：只有网页岗位要求表单的回归测试；分析规则靠虚构简历人工对照原文核对。
- **只写年份的时间**（如"2014–2024"）目前算不出任期。

## 项目结构

```
app.py              网页版：只做展示，判断复用命令行代码
main.py             单份简历分析入口（7 个模块并行）
screen.py           筛选入口：导入 JD、检查岗位要求、筛选、总览
setup_key.py        API Key 配置窗口
demo/               "看演示"用的虚构简历分析结果（tools/build_demo.py 生成）
parser/             读取文件、图片识别、脱敏
llm/                DeepSeek 调用和结果缓存
modules/            7 个分析模块
matching/           候选人画像、JD 解析、职责匹配、阅读队列、总览分层
knowledge/          知识库：院校排名、公司名单、竞赛目录、能力词典、岗位画像等
report/             文字报告、筛选理由、CSV
tools/              每年更新名单、爬取和统计校招 JD 的脚本
samples/            虚构样例简历、测试集和测试用 JD
tests/              网页回归测试（Playwright + Edge）
docs/开发说明.md     规则、关键决定、已知局限和进度
```
