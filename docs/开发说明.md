# 开发说明

本项目的规则、关键决定和进度（公开版）。**新会话开始时先读这份文件和 `CLAUDE.md`。**
文中例子全部来自虚构简历（`samples/`、`samples/test/`）；项目里不存放、不引用任何真实简历。

---

## 一、目标和定位

- **一句话目标**：给一批简历（有 JD 更好），告诉 HR **先看谁、为什么**。
- **定位**：中小企业校招季的 HR 助手。大公司有招聘系统；中小企业校招季邮箱里堆着几百份 PDF，看不过来。
- **卖点**：招聘系统按关键词过滤，没写关键词就被刷掉；本工具以**证据**为核心，不打总分、给理由、宁可多留、不确定的交给人判断。
- **目前只专注校招**；毕业后的全职工作并入实习经历一起分析，并提示"可能是往届生"。
- 作者是求职中的学生，这是作品集项目。

## 二、核心原则

1. **AI 只负责提取事实，所有判断由代码规则 + 知识库完成**：结果稳定、可解释。能用代码判断的不交给 AI（AI 每次结果不同）。
2. **不推测**：没写的就是没写；推断、默认值必须标注（"推断""AI 判断"），并提示 HR 核实。
3. **代码核对原文**：AI 填写的关键字段（学历、奖学金级别、职务、依据句）必须能在原文找到对应字样，否则视为没写。
4. **以证据为核心**：别人的决定（被选举、连任、放权、录用、获奖）> 可核验的具体行为 > 自述。输出**证据强度**，不输出"素质高低"。
5. **没写 ≠ 不会**：没体现的能力只排在后面，不淘汰；推断出来的事实碰到门槛只进"待确认"。例外：**要求的证书没写就算不符合**（用户决定：有证书的人几乎都会写）。
6. **不加权、不打总分**：加权会互相抵消、看不出原因、精确是假象。
7. **合规**：性别、年龄、民族、籍贯、婚育、政治面貌不作为筛选条件，界面不提供这些选项；报告末尾声明"仅辅助阅读，不作为录用依据"（《个人信息保护法》第 24 条对自动化决策的要求）。
8. **给 HR 看的文字不用内部术语**：代码里的深度 1～3 显示为"协助完成 / 独立负责 / 主导改进，有成果"；知识库的"基础"档显示为"其他本科"；界面不用"他 / 她"。
9. **不打补丁迎合测试简历**：规则、阈值、词典来自通用数据（JD 库、公开名单），结果对不上时先分"通用问题 / 个别情况"，个别情况记为已知局限。

## 三、工作方式（和作者约定）

- 先讨论思路和规则，作者确认后再写代码；作者常要求多轮"深度思考"，每一轮要找出上一版的根本问题，几轮后主动建议收敛、用执行检验。
- 规则和阈值由作者决定；给建议时说明理由。
- 涉及 3 个以上文件的改动，先给中文实施方案，确认后再写。
- 改完用虚构简历对照原文核对；改提示词后不用缓存跑两遍比较稳定性；改动前后对比报告，确认只改了想改的地方。
- 改完代码后**重启网页服务**再请作者看（Streamlit 有时不会重新加载被引用的模块）。

## 四、整体架构

```
简历文件 → 读取文字（PDF / Word / TXT / 图片识别）→ 统一字符 → 脱敏（手机号、邮箱、身份证号）
        → 7 个模块并行：AI 提取事实 → 代码核对原文 → 规则 + 知识库定档 → 文字报告 + 结构化画像
        → 画像合并成"证据列表" → ① 总览分层（不需要 JD） ② 阅读队列（需要 JD）
```

- 同一提示词 + 同一份简历只调用一次 AI（实习、校园、素质画像共用一次"经历提取"）。
- 画像里的证据：类型、名称、领域、深度（3 能构建 / 2 能解决问题 / 1 会操作 / 0 学过 / -1 自述）、情境（实习 / 全职 / 项目 / 校园 / 课程实习 / 团队项目 / 课程 / 自述 / 证书）、出处、原句。
- 情境说服力：真实工作 > 项目 > 校园 / 课程实习 / 社会实践 > 团队项目 > 课程 / 证书 > 自述。

## 五、分析模块的规则

### 基本信息
只做提醒，不参与评价。籍贯与应聘地点不一致时提醒，同时写明现居、求学城市作为背景。

### 教育背景（院校层次、学业表现、学业走势）
- **院校层次**：顶尖（清北华五、QS 前 50）/ 985（QS 前 100）/ 211·双一流（QS 前 200）/ 双非第一～第六梯队（软科主榜近 3 年平均名次，每 100 名一档）/ 其他本科（民办、独立学院）/ 专科。行业院校（财经、政法等只有类别榜）按类别内位置折算到主榜梯队。
- **学历缺失**：原文写明 → 按原文；专科院校 → 专科；AI 能从上下文判断 → 标"AI 判断"；否则按本科处理并标注。
- **学业表现**：排名（10 人以上）→ 绩点 / 均分 → 小样本排名。前 10% 优秀、前 30% 良好；4.0 制 ≥3.7 优秀、≥3.3 良好；均分 ≥90 优秀、≥85 良好。**以本科（专科生看专科）成绩为主**（HR 不太关注研究生成绩），本科没写才用研究生成绩并注明。
- **学业走势**：学历路径、院校层次提升 / 下降、推免、专升本、跨专业、空档期，只描述不分档。

### 证书荣誉（校内荣誉、竞赛、证书、科研成果）
- 奖学金按学历阶段定档：本科看次数和质量，研究生只看最高等级；单项奖励不计入学业奖学金。
- 竞赛以《全国普通高校大学生竞赛分析报告》目录为准，目录外最高"一般"；入围、优秀奖不算获奖。
- 科研成果：SCI / SSCI / CSSCI 一作或通讯、授权发明专利为优秀；其他已发表论文为良好；在投、软著为一般。
- 证书只分类不定档（价值取决于岗位）；四六级写法统一（CET6、cet-6、六级 → 英语六级），六级覆盖四级。

### 实习经历（平台、经历量、工作深度）
- 先分类：实习 / 全职 / 社会实践 / 课程实习 / 性质待核实。
- **平台**只按知识库名单定档（世界 500 强、头部机构 → 头部；中国 500 强、民企 500 强、A 股上市、独角兽 → 知名；其他 → 一般），不让 AI 猜公司知名度；分支机构按总公司，子公司只提示"疑似"。
- **经历量**：2 段以上且 ≥6 个月优秀；≥3 个月良好；时间重叠超过一半的两段算 1 段。
- **工作深度**（这个人承担了多少判断）：协助完成 / 独立负责 / 主导改进，有成果。说得越大证据要越多，"有成果"必须是被采用 / 通过或有数字的变化；**职位名称不参与定档**。职责变多（"中期起独立负责……"、留用、转正）作为亮点展示。

### 项目与技能
- 项目可信度：强 = 演示链接 / 代码仓库 / 论文专利 / 立项 / 导师课题 / 竞赛获奖；中 = 校级立项、毕设或有具体指标；弱 = 只有描述。
- 技能深度按"用它做出了什么"：能构建 / 能解决问题 / 会操作 / 学过（课程）/ 只有自述；广度单独列出，不定档。
- 团队项目概述里的技术只算"参与过使用该技术的团队项目"；自述"精通 / 熟练"而无佐证的，追问举例。

### 校园经历 + 素质画像
- 校园经历只描述和核查（角色、组织级别、任期、时间是否超出学历阶段）。
- 素质画像（责任心、主动性、影响力、学习成长、自我认知、严谨细致）：**素质属于人，不属于板块**，实习、校园、项目都是行为样本。AI 只识别信号（被选举、连任、自发组织、跨专业做成……），代码按映射表对应到素质；强 = 有别人的决定且 2 个以上情境。
- 沟通协作、抗压只能面试了解，不评价；输出证据强度，并给出行为面试问题。

## 六、JD 知识库

- **来源**：国家大学生就业服务平台（24365，教育部），无 robots 限制、不需登录、全是面向大学生的岗位。BOSS、猎聘、智联的 robots 禁止，应届生网有反爬验证，国聘要登录——都不爬。**只爬允许的来源、不绕过验证**，每秒最多 3 次请求，只保存 JD 文本、去掉联系方式；原始数据只存本地 `data/`，不上传。
- **第一版**：28 个校招常见岗位，1596 份 JD；只按内容去重（同一段 JD 挂在多家公司名下）、同一单位同一岗位最多 3 份。
- **统计**：AI（deepseek-flash）逐份提取技能、业务能力、素质、硬性要求，按能力词典归类，按岗位统计占比（核心 ≥50%、常见 ≥20%）。结果在 `knowledge/job_profiles.json`。
- **常见词表** `knowledge/common_words.json`：统计 2～4 字的词在多少比例的 JD 里出现（只存词和比例），用于判断 JD 职责关键词是泛词（≥20%）、常见词（5%～20%）还是具体词（<5%）。
- **能力词典** `knowledge/skill_domains.json`：约 30 个领域；只从 JD 库里词典外、出现 ≥5 次且能明确归类的词补充。**教训**：JD 库的统计不能直接说明简历里的词义（"清洗"在 JD 里多指数据清洗，但化学、食品专业简历里另有含义）。

## 七、导入 JD 和阅读队列（需要 JD）

- **导入**：AI 提取任职要求和岗位职责；找最接近的参考岗位；推荐"最看重"3 项；生成 `jobs/xxx.json`（工具的原始理解）和 `jobs/xxx.txt`（给 HR 改的文字文件，网页上是表单，两者走同一套读取核对流程）。
- **职责对上**：同一条经历原句出现 2 个关键词（且领域不冲突），或 1 个具体词且这句话能识别出同一领域。
- **能力证据**：先比具体名称，再比领域（标"相近"）；宽泛领域（1/3 以上岗位都常见，如数据处理与分析、编程开发）不比领域。
- **五个队列**：优先看 / 值得看 / 可以后看 / 硬条件不符（确定的事实）/ 需人工查看（PDF、图片解析异常）；每人附理由和最多 3 个电话初筛问题。

## 八、总览分层（不需要 JD）

- 9 个维度：学校层次、学历、学业成绩、实习经历、项目经历、技能、通用素质、证书荣誉、岗位匹配（需 JD）。学业走势只显示；硬性要求（最低学历、院校层次、专业、证书）只筛选。
- **分层规则**：只有在所选每一项上都不比别人差、且至少一项更好，才排在前面；否则"各有所长"放同一层。原来"先比第一项、相同再比下一项"等于给第一项无限大的权重，10 个人排出 9～10 个名次，是虚假的精确。每人给出"为什么"（没被全面超过、哪几项最好；或被谁全面超过、哪几项更好）。建议勾 2～3 项。
- **档位细度和判断可靠程度匹配**：学校层次来自外部排名，用细档；实习、项目深度从措辞判断，只用粗档，时长、平台只显示。
- 学历是门槛（达到即可），默认不参与排序；学校层次看哪一段由 HR 选（默认先看最高学历，相同再看第一学历）。
- **已知特点**：很多人是"无"的那一项，谁有一点就能避免被全面超过（虚构测试集里只做过一段"协助"科研的 D5 和实习很强的 D2 同层），"为什么"里写得清楚。

## 八之一、结果页：在一页里做完初筛

HR 的真实任务是"逐份看、逐个决定"，不只是看排序，所以结果页按这个流程设计：

- **视图**：确认了岗位要求默认看阅读队列，可切到总览；没有岗位要求只有总览，顶部提示可以去导入。
- **完整分析**：第一页是"为什么在这里"（阅读队列的理由，或总览的层和各项情况），之后是各模块，**基本信息（籍贯、现居城市等）放在最后**，避免先入为主；再后面是"原简历"和纯文字版。
- **原简历**：PDF 逐页转成图片，图片直接显示，Word / TXT 显示读出来的文字（`read_bytes` 在内存里读，不写临时文件，和分析用的 `read_file` 共用同一套解码和收尾，结果完全一致）；原文件只在网页内存里，不写硬盘。
  - PDF 清晰度：每页按 1460 像素宽渲染（Streamlit 显示图片最宽 1460，再宽会被它缩小一次），分辨率限制在 150～200 DPI（A4 约 176 DPI）；PDF 页面用 PNG 显示（默认会存成 JPEG，文字边缘发虚）；按原尺寸显示、只缩不放。原来固定 110 DPI + 拉伸到弹窗宽度 + JPEG，150% 缩放的屏幕上放大约 1.3 倍，文字发虚。实测边缘锐度 1458 → 1912。渲染每页约 30 毫秒，暂不需要换 PyMuPDF。
  - 「下载原文件」：原样下载上传的文件（逐字节相同），用本机软件看原始清晰度；150% 以上缩放的屏幕上网页里的图仍会被浏览器略微放大，要看细节用这个。
- **需人工查看**的人（解析异常，不参与分层）在总览里没有表格行，提示旁边有「查看原简历」：弹窗只放原因、原简历和"通过 / 待定 / 淘汰"，不进完整分析（模块可能是空的），没有"下一份"（不在阅读顺序里）；原文件不在时按钮变灰。"已处理 x / n"的 n 包括这些人，两种导出表格里都有他们的行和决定。和完整分析的原简历页共用同一个显示函数。
- **决定**：弹窗顶部"通过 / 待定 / 淘汰 / 下一份"；标记后自动打开当前列表里下一位**还没处理**的人（后面没有就从头找）。顶部显示"已处理 x / n 人"，总览表格和队列卡片显示决定，两种导出表格都有"决定"一列（命令行版留空）。
- **决定只存在这次打开的网页里**，刷新就没有了，靠导出表格留存；不写硬盘，少一个存放个人信息的地方。

## 九、隐私和数据保存

- 上传的简历文件分析完立即删除（临时文件）；分析结果、原文件内容（"原简历"页用）和 HR 的决定只在这次打开的网页里。
- AI 从简历提取的内容缓存在 `.cache/resumes/`，**30 天后自动删除**（按写入时间），网页侧边栏可一键清除；公开 JD 的提取结果在 `.cache/jd/`，长期保留。
- API Key：网页侧边栏填写，默认只在本次页面使用，勾选才写入本机 `.env`；连接失败不显示接口原始报错。
- 项目里不放任何真实简历（隐去个人信息也不行）；测试和演示只用虚构简历。

## 九之一、公开部署模式（`PUBLIC_DEMO=1`）

网页原本按"自己电脑上用"设计，直接放到公网会有问题，所以用一个开关区分（环境变量或 Streamlit secrets 里的 `PUBLIC_DEMO=1`）：

| 项目 | 本机 | 公开模式 |
|---|---|---|
| API Key | 读 .env / 环境变量；网页可勾选保存到本机 | **只用访客自己填的**（否则所有访客都在花部署者的钱），不能保存 |
| 简历缓存 | 硬盘 30 天 | 不写硬盘；AI 客户端只存在访客自己的页面里 |
| 岗位要求 | 保存到 `jobs/` | 不保存（否则访客之间互相看到） |
| 份数 | 不限 | 一次最多 20 份 |

- **看演示**：读 `demo/` 里预先生成的 11 份虚构简历结果 + 一份确认好的岗位要求，不需要 Key、不调用 AI；规则改了要运行 `python tools/build_demo.py` 重新生成
- 部署到 Streamlit Community Cloud：`requirements.txt` 补了 `onnxruntime`（图片识别实际运行需要，原来只是本机碰巧装了）；`packages.txt` 安装 OpenCV 需要的系统库

## 十、性能

- 目标：单份 ≤10 秒，100 份 ≤3 分钟；质量优先，所有模块做完后再整体优化。
- 实测：每份 5 次 AI 调用并行，总耗时约等于最慢的一次；长简历约 13～20 秒，主要由输出长度决定（项目与技能模块输出最多）。deepseek-flash 比 pro 快约一倍，是否切换待定。

## 十一、已知局限（不打补丁）

- **逐字比对**：职责和能力是按字面比较的，同一件事换一种说法就对不上（JD 写"数据模型"、简历写"建模"），字面巧合又会误中（"清洗实验器皿"）。虚构测试集已证实。解决方案"工作活动表"（从 JD 职责整理约 100 项标准活动，AI 把两边都归到表里，代码比较）已设计、暂缓。
- 只写年份的时间（如"2014–2024"）目前算不出任期。
- 大学前开始的任职会被记为"时间与学历阶段对不上"（严谨细致的反向信号），即使原文写明了年数。
- 速度未达目标；分析规则尚无自动回归测试（网页表单和文件读取各有一个，见"测试"一节）。
- TXT 编码：只认 UTF-8（含 BOM）和 GBK；UTF-16、含 GBK 以外生僻字的 GB18030 文件会整篇读成乱码。Word 的页眉页脚不读。（2026-10-01 改代码前实测，读文件和读内存一致，暂未处理）

## 十二、踩过的坑（通用）

- **PDF 里的"部首字符"**：部分导出工具把常用字存成康熙部首（"硕⼠"的"⼠"是 U+2F20），看起来一样但代码找不到"硕士"。读取时统一换成正常汉字。
- 关闭思考后 AI 更容易按常识补全（学习形式、级别）→ 代码核对原文。
- 提示词加长会让 AI 漏提取 → 格式固定的内容改由代码识别，改提示词后不用缓存跑两遍。
- 核对太严会丢有效信息（网址少一个字母、两处拼成一句）→ 用原文写法替换、按分号拆开保留找得到的部分。
- 同一个词语境不同意思不同（"辅助 HR 自查"是产品用途，不是本人协助）。
- 官方名单只发长图 → 图片识别后检查序号连续。
- 部分服务器会断开 Python 网络库或 IPv6 连接 → 改用 curl、加 `-4`。
- **网页表格编辑时报 `removeChild` 错误**
  - 问题：岗位要求表单里每改一格表格就整页刷新，刷新和表格下拉框的关闭动作撞车，页面报 "Failed to execute 'removeChild' on 'Node'"（用户实际遇到两次，无痕窗口也有，和翻译插件无关）。
  - 原因：时序问题，取决于点击快慢，无头浏览器和 Edge 都复现不了。
  - 修复：表单改用 `st.form`，填写时不刷新，点「确认岗位要求」才一起生效；代价是表格里新加的能力要确认一次后才能选为"最看重"。
  - 验证：统计编辑时发给服务器的刷新请求。同样三步编辑（选"院校"、填内容、勾"必须"），旧版 `980aee1` 为 1 + 1 + 1 = **3 次**，新版 **0 次**，点确认时 1 次。已固化成 `tests/test_job_form.py`：对旧版运行会失败（退出码 1），对新版通过。**注意：它验证的是"触发条件消失"，不能直接复现原始报错**；运行时也监听页面错误和控制台错误，出现 removeChild 同样判失败。
- 命令行里用 heredoc 写 Python 时，`"\n"` 可能被转成真换行导致语法错误 → 长修改改用写文件的方式。

```bash
python tests/test_job_form.py --shots     # 另存编辑后的截图到 tests/output/，人工核对三步编辑确实做了
python tests/test_job_form.py --root 目录  # 测另一份检出，例如 git worktree add --detach ../旧版 980aee1
```

| 测试 | 检查什么 |
|---|---|
| `tests/test_file_reader.py` | `read_bytes`（读内存）和 `read_file`（读文件）结果完全一致：samples 里所有虚构 TXT / Word、现场生成的复杂 Word（合并单元格、表格套表格、多种样式、文本框）、8 种 TXT 编码情况（读错的要"错得一样"）；不需要浏览器，`python tests/test_file_reader.py` 或 pytest |
