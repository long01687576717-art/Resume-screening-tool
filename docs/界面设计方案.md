# 界面设计方案（草案，待作者决定）

目标：让网页看起来像一个**可信、专业的 B2B HR 产品**——中小企业 HR 愿意把简历放进来用，面试官打开作品集链接 10 秒内看懂它是什么、为什么靠谱。
下面每一项都给出选项和推荐，**决定权在作者**。标 ✅ 的是 `ui-design` 分支原型里已经做了的。

## 一、参考了哪些产品、学到了什么

调研方式：只看公开官网首页（2026-09-30），用网页抓取工具读页面文字结构，并查看了部分页面源码里的字体和主题色；**没有用浏览器肉眼逐页看视觉效果**，所以下表以"结构、文案、信任信号"为主，视觉细节只写有依据的。没有复制任何标志、图片、插画或文案，只取原则。

| 产品 | 首屏标题的写法 | 主要按钮 | 信任信号怎么摆 | 产品界面怎么展示 | 学到的原则 |
|---|---|---|---|---|---|
| Moka（mokahr.com） | 短句口号 + 一行副标题 | "免费试用"为主，"了解更多"为辅 | 客户数（3000+ 企业）、客户标志墙；安全认证（等保三级、ISO、CSA、数据隔离）集中放在一处 | 功能分区里嵌真实界面截图 | 安全合规要**集中、成组**地摆，不散在各处 |
| 北森（beisen.com） | 能力定位式口号 | "预约演示""预约体验"反复出现 | 大数字（6000+ 客户、年测评量等）；源码里主色为饱和蓝 #2E56FF | 每个产品一张缩略图 + 一句说明 + 链接 | 用**可核实的数字**建立规模感；我们要避开它的蓝，做自己的色 |
| 钉钉（dingtalk.com） | 一句主标题 + 一句副标题 | 两个并列下载按钮 | 用户规模 + "等保三级、数据全链路加密"紧跟在标题下面 | 产品图在功能介绍之后 | 安全承诺可以**紧贴首屏**，一句话即可 |
| 飞书招聘（feishu.cn/hire） | —— | —— | —— | —— | 页面由脚本渲染，抓取工具读不到内容，**未能调研** |
| Greenhouse | "Better signal. Human judgment. One platform."：三个短句 | "Request a demo" | 客户标志、奖项；页脚放**伦理原则、AI 原则、偏见审计**链接 | 功能卡片里放界面截图 | 招聘软件专门交代"AI 怎么用、人来判断"，和我们"只排顺序、人做决定"完全同调 |
| Lever | 利益点标题（不占用你一周） | "See Pricing" + "Get a Demo" 两条路 | 具名客户评价、G2 徽章 | 交互式界面样机 | 主按钮 + 次按钮给**两条路**（试用 / 了解） |
| Ashby | 4 个词的判断句 | "Get in Touch" | 客户标志网格；SOC 2 放页脚 | 产品导览区 | 标题越短越自信 |
| Workable | 一句对比句 | "Start a free trial" + "Request a demo" | 关键数字一行三个；ISO 27001、SOC 2、GDPR、EEO 列在一起 | 首屏就放产品界面图 | **首屏数字条**：3～4 个数字排一行 |
| Workday（招聘产品页） | 一句标题 + 一句说明 | "Play Demo (2:40)" | 百分比成效，并**注明数据来源** | 首屏是真实工作台截图 | 数字要**标来源**，否则不可信 |
| Linear | 一句定位 + 一句补充 | 一个主按钮 | 客户评价、使用团队数 | **真实产品界面**而不是插画；主题色 #08090a（深色） | 让产品自己说话：演示就是最好的截图 |
| Stripe | 8 个词标题 + 17 个词副标题 | "Get started" | 客户标志轮播；一整行大数字（交易额、可用性 99.999%） | 便当格（bento）卡片 | 数字条 + 克制的配色；源码用 Söhne 字体、正文近黑色 |
| Notion | 8 个词标题 | 主"免费用" + 次"预约演示" | 标志墙 + 统计数字 + 评价 | 三个功能支柱各配界面图 | 主次按钮的层级非常清楚 |
| Vercel | 两个词的标题 | "Deploy now" + "Talk to sales" | 客户案例带具体数字 | 用案例代替截图 | 源码用自家 Geist 字体、#FAFAFA/黑白为主：**极度克制，只有一种强调色** |

**共同点（我们的设计原则由此而来）**

1. **首屏只说一件事**：一句短标题（≤ 15 字）+ 一两句副标题，写"给谁、解决什么"，不写功能清单。
2. **一个主按钮，最多一个次入口**：主按钮颜色最重，次入口是文字链接。
3. **信任靠事实**：可核实的数字（带来源）+ 安全合规要点成组出现；不堆形容词。
4. **一种强调色 + 大量中性灰**：颜色只用在"要你点"和"有固定含义"的地方。
5. **展示真实产品界面**：我们的"看演示"就是真实界面，而不是插画。
6. **招聘软件要主动交代 AI 边界**（Greenhouse 的 AI 原则、偏见审计）：我们的"只排阅读顺序、不打分、不做录用决定"要放在显眼但平静的位置。

**Streamlit 能做到多少**：1、2、3、5、6 基本都能做到（本分支已做）；4 能做到八成（主题配置 + 少量 CSS）。做不到的：自定义字体的精细排版（中文字体文件很大，不建议引外部字体）、流畅的动效和悬停细节、营销页那种整屏大图和滚动叙事、文件上传控件的英文文字（"Upload / 200MB per file"是 Streamlit 自带，改不了）。

## 二、谁在看、前 10 秒要看到什么

| 访客 | 他想知道 | 首屏必须有 |
|---|---|---|
| 中小企业 HR（校招季，邮箱里几百份 PDF） | 这东西能不能帮我省时间？我的简历数据安全吗？会不会乱刷人？ | 一句话价值："一批校招简历，先看谁、为什么"；**看演示**按钮（不用 Key、不花钱）；隐私要点一行 |
| 面试官（打开作品集链接） | 做了什么？是否专业、有思考？ | 同上 + 事实数字（7 个模块、28 类岗位、1596 份公开 JD、0 个总分）+ 规则公开的链接 |

推荐：首屏 = 品牌行 → 标题 → 副标题 → [🎬 看演示]（主按钮）+「或者直接上传自己的简历 ↓」→ 数字条；下面紧跟一行隐私/合规徽章。✅

## 三、品牌

**产品名（选一个）**

| 选项 | 说明 |
|---|---|
| **简历初筛助手**（推荐，现名） | 直白，HR 一看就懂；已写进 README、部署地址 |
| 先看谁 | 口语化、好记，就是产品的核心问题；但不看说明猜不出是简历工具 |
| 循证初筛 | 突出"以证据为核心"；偏学术 |

推荐保留"简历初筛助手"，把"先看谁、为什么"当副标题 / 标语用。✅

**标志**：蓝底圆角方块，里面三条由长到短的白色横线（一批简历排出先后），最上面一条后面打勾。用内嵌 SVG 画，不依赖外部图片，不涉及商标。✅（`ui/style.py` 的 `LOGO`）
备选：文字标志"筛"字方块；或只用 📋 表情（现状，最省事但最不像产品）。

**配色**（对比度按 WCAG 计算，白底）

| 用途 | 颜色 | 对比度 | 规则 |
|---|---|---|---|
| 主色（墨蓝） | `#1F4FD1` | 6.8 : 1 | 只用于主按钮、链接、进度条当前步、步骤编号；一屏里只出现一个主按钮 |
| 正文 | `#111827` | 17.7 : 1 | 近黑，不用纯黑 |
| 次要文字 | `#5B6474` / Streamlit 自带灰 | ≥ 4.5 : 1 | 说明文字、注释 |
| 边框 | `#E4E7EC` | —— | 卡片、表格、输入框 |
| 浅底 | `#F5F7FA`（区块）、`#F8FAFC`（侧边栏） | —— | 表格隔层底色、侧边栏 |
| 队列色 | 绿 = 优先看、蓝 = 值得看、灰 = 可以后看、橙 = 硬条件不符、紫 = 需人工查看 | Streamlit 内置 | **含义固定，不挪作他用** |
| 提示 | 黄 = 待核实，红 = 出错 | 内置 | 只在确实需要 HR 注意时用 |

原来的主色 `#2F6FEB` 在浅灰底上对比度只有 4.2，达不到正文要求，所以加深。注意：主色蓝和"值得看"的蓝相近，靠"徽章形状 + 文字"区分；如果作者介意，可以把主色换成靛青 `#2449C8`（7.3 : 1），或把"值得看"换成青色（需要改 `QUEUE_STYLE`，属于显示层）。

**字体与间距**
- 字体：不引外部字体。中文会自动落到系统字体（Windows 微软雅黑、Mac 苹方），英文数字用 Streamlit 自带无衬线。
- 字号层级：首屏标题 26～38px（随屏宽变化）粗体；步骤标题 22px 粗体；正文 16px；说明 13～14px。只用 3 种字重（400 / 600 / 700）。
- 间距：卡片内边距 16～32px，圆角统一中等（约 8px，品牌区 16px）；区块之间靠卡片分隔，不再用分割线。

## 四、信息架构和布局

- **品牌区**：未分析时完整展示（标题 + 按钮 + 数字）；分析完或载入演示后收成一行（品牌 + 看演示按钮），把位置让给结果。✅
- **三步进度条**：三个可点击的小卡片，已完成打 ✓（主色实心），当前该做的一步高亮，每步下面一行状态（"已确认：数据分析工程师""已分析 11 份"）；点击跳到对应步骤。✅
- **每一步一张卡片**：编号方块 + 标题 + 一行说明，统一样式。✅
- **空状态**：第 ③ 步没有结果时，用虚线框 + 图标 + "还没有结果" + 下一步该做什么（含"看演示"提示），而不是一行小字。✅
- **加载状态**（建议，未做）：分析简历时把进度条换成 `st.status`，展开能看到每份简历"读取 → 提取 → 判断"的进度；出错的那份直接显示在里面。
- **错误状态**（建议，未做）：错误用一句人话 + 下一步（"这份文件读不出文字，请直接打开原文件"），原始报错折叠起来。
- **结果页的层级**：先总数（队列指标卡，带队列颜色徽章 ✅）→ 再每人一张卡片（理由）→ 需要时再点"完整分析"弹窗（摘要卡片 + 分模块标签页，已有）。
- **表格可读性**（建议，未做）："为什么"列经常被截断：可以给它更宽的列宽，或把长理由放到选中行下方的详情里。
- **窄屏 / 手机**：品牌区内边距缩小，进度条改成竖排，数字条换行。✅（CSS 媒体查询；Streamlit 自己会把分栏竖排）
- **页脚**：产品名 + "仅辅助阅读，不作为录用依据" + 规则和代码公开的 GitHub 链接。✅

## 五、信任与合规信号（平静地说，不堆法律条文）

- 首屏下方一行灰色徽章 ✅：
  - 公开版"不保存简历，关掉页面就消失"；本机版"AI 提取结果只存本机，30 天自动删除"
  - "手机号、邮箱、身份证号不发给 AI"
  - "不按性别、年龄等筛选"
  - "只排阅读顺序，不做录用决定"
- 详细说明仍在侧边栏「设置 → 隐私」（原样保留）；结果页底部保留原有的合规声明。
- 规则公开：页脚 GitHub 链接 ✅。建议以后加一个"判断规则说明"弹窗（`st.dialog`），用 5 句话讲清"证据分级、没写 ≠ 不会、不打总分"——对应 Greenhouse 的"AI 原则"做法。
- 右上角菜单改为只显示查看选项（`toolbarMode = "viewer"`），"关于"里写一句产品说明。✅

## 六、Streamlit 能做什么、哪里容易坏（本机 1.64）

| 手段 | 能做什么 | 稳定性 |
|---|---|---|
| `.streamlit/config.toml` 的 `[theme]` | 主色、底色、文字色、边框色、圆角、标题字重、表格表头底色、指标数字大小、侧边栏底色 | **最稳**，官方配置项。注意：`requirements.txt` 写的是 `streamlit>=1.45`，部分新配置项（如 `baseRadius`、`metricValueFontSize`）旧版本不认识，只会被忽略，不会报错；云端默认装最新版 |
| 原生组件 | `st.badge`（徽章）、`st.metric(border=True)`（指标卡）、`st.container(border=True / horizontal=True)`、`st.tabs`、`st.dialog`、`st.segmented_control`、`st.status`、分栏 | 稳 |
| `st.container(key="rs_xxx")` + CSS `.st-key-rs_xxx` | 给某一个容器单独加样式（品牌区渐变底、步骤卡片圆角） | 较稳：官方文档写明 key 会变成 `st-key-` 开头的 class |
| `st.markdown(unsafe_allow_html=True)` / `st.html` | 自己写的小块 HTML（标志、进度条、空状态、页脚），class 都用 `rs-` 开头 | 稳：只依赖自己起的 class |
| 用 Streamlit 内部 `data-testid` / 自动生成的类名写 CSS | 改控件内部细节 | **容易坏**，升级后可能失效。本分支只用了 1 处（缩小页面顶部留白），失效也只是留白变回原样 |

做法：CSS 集中在 `ui/theme.css` 一个文件（约 100 行），开头写明规则；颜色用半透明，深色主题下也能看；显示用的小部件在 `ui/style.py`，只排版文字、不做判断。
